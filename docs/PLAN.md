# STB Editor: архитектура и рабочий план

Актуализировано 2026-11-11. Последний описанный релиз — 0.76.0; изменения оболочки, скриптов алиасов,
коллизий и AI/MCP ниже относятся к **Unreleased**, а не к новому выпуску.
Функции и ограничения — [README](../README.md), подробная сверка с CK/xEdit — [GAPS.md](GAPS.md),
короткий план для тестеров — [ROADMAP.md](ROADMAP.md), история — [CHANGELOG](../CHANGELOG.md).

## Цель и границы

Отдельный редактор для Windows: загрузка Skyrim SE / AE / VR / GOG через профиль MO2 или обычный `Data`,
расстановка объектов, ячейки и миры, ландшафт, навмеш, редактирование записей, квестов, диалогов,
сцен и AI-пакетов. Поддерживаются ESP / ESM / ESL, header 1.70 и 1.71 с ограничениями версии игры/BEES.
Один активный файл принимает правки; остальные плагины — источники данных и мастера.

Papyrus уже поддерживается: исходники, внешний PapyrusCompiler, свойства VMAD и фрагменты квестов,
диалогов, пакетов, сцен и перков. Нужен установленный компилятор и его импорты; это не встроенная
реализация языка. Скрипты алиасов и их свойства доступны в текущей unreleased-версии.
Не заявляем полную совместимость со всеми окнами CK: оставшиеся пробелы перечислены отдельно.

## Реализованная архитектура

Один процесс .NET 10, Win32 + Dear ImGui docking (Hexa.NET.ImGui), D3D11 (Vortice), ImGuizmo.
UI не требует выбора между Avalonia/WPF/ImGui: выбор сделан и реализован.

| Проект | Ответственность |
|---|---|
| `Editor.Data` | GameInstall, MO2/load order, Workspace с Mutagen overlays, FormID ↔ FormKey, RecordLookup, каталог и Use Info с дисковыми кэшами, PapyrusCompiler, сырой TES4-слой `Raw/` |
| `Editor.Assets` | AssetFileSystem: loose по приоритету MO2 поверх BSA; чтение архивов, BSA writer, PEX |
| `Editor.Nif` | Ручной читатель NIF для рендера: геометрия, материалы, эффекты, скиннинг в позе привязки, коллизия; ограниченный block-level writer для FaceGen, TRI |
| `Editor.Render` | SceneBuilder, GPU-кэши, SceneRenderer/HLSL, CPU Picking, камера, частицы, трава, FaceGen, физическое падение объектов |
| `Editor.Core` | EditDocument, команды undo/redo, черновики записей/земли/навмеша, RecordFields, PluginWriter, проверки, генерация навмеша DotRecast и инструменты записей |
| `Editor.App` | Win32-цикл, панели, локализация RU/EN, темы/масштаб, сохранение и настройки, рабочие раскладки, пользовательские C#-скрипты, необязательный AI/MCP-мост |
| `Editor.Cli` | Диагностика форматов, данных и воспроизводимые проверки без GUI |

Поток: `Workspace` → `RecordCatalog` / `RecordLookup` → `SceneBuilder` → `SceneRenderer`.
Правки идут в `EditDocument`, применяются к сцене и формам до сохранения, затем `PluginWriter`
пишет активный плагин. `RecordFields` — единый слой обхода/правки полей для UI и инструментов;
не создавать второй редактор схемы записи рядом с ним.

### Решения, которые нужно сохранять

- **Данные — Mutagen плюс сырой слой.** Нет SQLite-индекса и генератора NIF-классов из `nif.xml`:
  это были ранние варианты, не описание текущего кода. Каталог и Use Info имеют собственные
  дисковые кэши. Записи ищутся типизированно; нельзя индексировать все REFR через untyped LinkCache.
- **Сохранение в активный файл.** Правка чужой записи становится override. Writer сериализует
  изменения, `RawSplice` возвращает исходные байты нетронутых записей. Добавление/перестановка
  мастеров требует перенумерации и полного rewrite: это исключение из гарантии байт-в-байт,
  а не незаметная нормализация. Перед заменой — проверка чтением, временный файл и бэкап.
- **Кодировка на строку.** Строгий UTF-8 с cp1251 fallback при чтении; запись — в преобладающей
  кодировке плагина. Локализованные мастера читаются с их источниками строк; запись `.strings`
  ещё не реализована.
- **MO2 без usvfs.** Профиль и приоритеты ассетов читаются напрямую. Плагин сохраняется в выбранный
  активный файл; компиляция Papyrus, FaceGen и другие экспорты могут отдельно писать ассеты рядом
  с ним. Поэтому тесты используют scratch-плагин вне игры/модов.
- **Undo/redo над документом.** Обычные правки и групповые операции используют существующие команды.
  Наличие undo не означает транзакционность произвольного C#-кода или его внешних файловых эффектов.
- **Рендер — приближение, не игра.** CPU-пикинг, reversed-Z, D3D11, ландшафт, вода, эффекты и актёры
  в bind pose. Нет обещания игрового FPS, полного LOD, теней или проигрывания анимаций актёров.
  Точные границы — [RENDERING.md](RENDERING.md).
- **Рабочая оболочка.** World / Records / Classic меняют докирование, но сохраняют документ,
  сцену и выбор; пользовательский `layout.ini` не заменяется при запуске. Темы, масштаб,
  RU/EN и специализированные формы используют общие механизмы, а не отдельный UI-фреймворк.

## Что уже закрыто из исходных этапов

Данные и 3D-просмотр; расстановка/сохранение; generic и специализированные формы, сравнение,
Use Info и условия; новые ячейки/миры и их свойства; ландшафт с текстурами и цветами;
ручной навмеш, Finalize и генерация; квесты/диалоги/сцены/пакеты с Papyrus; FaceGen;
проверки ITM/UDR, мастера, ESL, BSA, перевод текстов, merged/delta patch и C#-скрипты.
Это реализованные возможности, не утверждение, что все варианты игровых данных проверены.

Unreleased добавляет рабочие раскладки и адаптивные формы/toolbar, редактор скриптов алиасов,
исправление обхода convex hull через Bepu 2.5.0-beta.33 и обобщение локального MCP-доступа.
Номера релиза для этих изменений пока нет.

## AI/MCP: зачем оставляем

[AI-BRIDGE.md](AI-BRIDGE.md) описывает необязательный локальный HTTP MCP-сервер для совместимого
клиента, независимо от выбранной модели. Он даёт готовый доступ к несохранённому документу,
загруженной сцене, камере/снимкам, структурированным FormKey, обычным undo-правкам и предложениям,
которые решает пользователь. Это полезнее чтения только ESP на диске для задач в живой сессии.

Это не уникальная способность Claude: агент с shell и исходниками может написать альтернативный
IPC или тестовый harness. Мост экономит эту работу и даёт единый интерфейс, но не делает любой
отдельный языковой движок MCP-клиентом. Claude Code chat остаётся отдельным необязательным
launcher для установленного `claude`, не универсальным провайдером моделей.

Сервер и прямые правки имеют отдельные разрешения; unsandboxed `run_script` требует ещё одного
явного opt-in (`AiBridgeScripts`, по умолчанию false). Нет общей гарантии «AI не может писать файлы».

## Следующие приоритеты

Порядок — ориентир для выбора задачи, не обещание сроков. Полные ограничения — [GAPS.md](GAPS.md).

1. **Надёжность существующих операций.** Расширять воспроизводимые сценарии для реальных данных,
   roundtrip и сохранения; не считать наличие флага `--autotest-*` доказательством его прохождения.
   После правок схем/VMAD/мастеров проверять именно затронутый путь и нетронутые данные.
2. **Доделать ежедневные операции CK/xEdit.** Deep copy/перенос между плагинами, запись локализованных
   `.strings`, экспорт стадий/целей квеста; отдельно уточнять семантику ссылок и побочных файлов.
3. **Остаток инструментов мира.** Cover edges/оптимизация/отрицательные объёмы навмеша,
   Join/Break Occlusion Planes, течения воды/Water Flow, изометрический вид.
4. **Предпросмотр и модовые конфиги по запросам.** IED, SkyPatcher/CDF, генерация объектов регионом;
   облака/осадки/image space — только с честным указанием границ предпросмотра.
5. **Узкие MCP-инструменты по реальной задаче.** Проверки плагина/навмеша и предложения правок
   полей без необходимости давать unsandboxed C#; не добавлять сетевой AI-сервис или абстракцию
   провайдеров без отдельной потребности.

## Как проверяем и публикуем

Команды и сценарии — [DEVELOPING.md](DEVELOPING.md): `Editor.Cli` и встроенные `--autotest-*`,
roundtrip отдельных записей, сравнение нетронутых байтов при сохранении, снимки UI/рендера.
Нет отдельного проекта `Editor.Tools`, SKSE-плагина `link/` или каталога тестов, обещанных ранним
планом. Сценарии запускаются на scratch-выводе, не в игре/модах; настройки приложения восстанавливаются.
Результат проверки относится только к реально запущенному сценарию, не ко всей функциональности.

.NET SDK 10; сборка/PR и выпуск архива настроены в GitHub Actions. Релиз появляется после отдельного
раздела версии в changelog, коммита и тега; `Unreleased` не следует выдавать за опубликованную сборку.

## Исторические варианты, не текущие обязательства

Первый план от 2026-10-10 предлагал SQLite, NIF-codegen/редактор, отдельные `Editor.Tools`/`tests`,
SKSE live-link, autosave/журнал восстановления и не включал компиляцию Papyrus. Они не описывают
нынешнюю архитектуру. NIF-редактор не входит в цель; FaceGen writer не является общим NIF-редактором.
SKSE live-link не реализован и не стоит в ближайшей очереди; локальный MCP-мост к редактору его
не заменяет и не подключается к работающей игре. Собственный LOD-генератор не планируется —
для этого остаются xLODGen / TexGen / DynDOLOD.

[ANALYSIS.md](ANALYSIS.md) сохраняет исходный бинарный разбор и рекомендации как историческое
свидетельство, а не альтернативную актуальную дорожную карту.
