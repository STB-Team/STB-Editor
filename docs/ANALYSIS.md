Дата: 2026-10-10. Источники: бинарники мода `C:\Skyrim\[STB] Mod Organizer\mods\SkyrimMapEditor`
(архив `Downloads\SkyrimMapEditor-1.0.0.zip`), без исходников. Структура восстановлена по PDB,
метаданным .NET-сборок и строкам DLL.

> от 2026-10-10. Актуальная архитектура — [PLAN.md](PLAN.md), реализованные возможности —

## 1. Что такое концепт

Внутреннее имя — **ElderEditor**. Это **редактор внутри работающей игры**, а не отдельная программа.

| Часть | Технологии | Роль |
|---|---|---|
| `SkyrimMapEditor.dll` (SKSE) | C++23, CommonLibSSE-NG (SE+AE через `VariantID`), xmake, Dear ImGui + ImGuizmo, D3D11, spdlog, nlohmann_json | UI, камера, выбор, гизмо, отображение маркеров, документ правок, журнал восстановления |
| `SkyrimMapEditor.Writer.exe` (.NET 9) | Mutagen | получает JSON-«снимок» правок и пишет ESP |
| `Writer.Broker.exe`, `Publisher.exe` (натив) | — | запуск писателя; **публикация в MO2 после выхода из игры** (из-за VFS MO2 запись из игры уходит не туда) |

Консольная команда `skme` включает сессию; редактор перезапускает игру в «новую игру» и делает `coc`
в нужную ячейку.

### Модули (из PDB)

- `EditorSession` — вход/выход, каталог ячеек, телепорт по `coc`.
- `EditorCamera` + `Reverse/CameraHooks` — свободная камера поверх `ThirdPersonState`
  (Update/GetRotation/GetTranslation), блок зума.
- `Reverse/WorldStreamingHooks` — **подмена центра грида**: ячейки грузятся вокруг камеры, а не
  игрока (хук на `PlayerCharacter` → позиция, ID 35565/36564 и смещения 1129/2067). Ключевой приём.
- `SelectionPicking` — **GPU-пикинг**: рендер ID объектов в отдельный таргет с depth-тестом по
  глубине сцены, чтение одного пикселя.
- `SelectionOutline` — обводка выделенного (маска + шейдер расширения на 3 px).
- `EditorSelection` — выбор + ImGuizmo (move/rotate/scale, snap 16–256 units, 22.5°).
- `EditorMarkers`, `EditorVisibility(+Hooks)`, `EditorLODVisibility`, `LODRoots`, `EmittanceHooks`,
  `LightHooks` — показ маркеров (room/portal/occlusion/collision volume, light, tree, flora),
  отключение воды/тумана/LOD, свет.
- `EditorNavMeshes` — **только показ** навмеша.
- `ObjectSpawner` + `FormBrowser` — каталог форм по категориям, drag&drop в мир.
- `EditorWorldState` — погода, время суток, глушение звука.
- `MeshPreviewCache` — превью мешей через сторонний `MeshRenderingFramework` (опционально).
- `EditorCore/*` — документ, операции, undo/redo, `RuntimeIdentityMap` (runtime FormID ↔ запись),
  `RecoveryJournal`, `SavePipeline` с поколениями, отпечатки SHA-256 мастеров, атомарная замена.

### Что умеет писатель (полный список, по метаданным)

- создать / сдвинуть / повернуть / масштабировать REFR;
- «удалить» ванильный реф безопасно (`ApplySafeDisable`: disable + enable parent, а не удаление);
- свойства света (база LIGH и per-ref `XLIG`: radius, fov, fade, flicker, depth bias…);
- создать **интерьерную** ячейку (с дефолтным освещением);
- проверка, что нетронутые записи остались **байт-в-байт** (`PluginBinaryInventory.ValidateUntouched`).

Ограничения, прямо записанные в строках: `ESL-flagged ESP targets are not supported yet`,
`Writer v1 does not support removing a saved interior CELL`, цель — только активный `.esp`.

## 2. Оценка концепта

**Сильные стороны (идеи, которые стоит взять):**
1. Картинка = игра: свет, ENB/Community Shaders, LOD, вода — без своего рендера.
2. GPU-пикинг по ID-буферу и обводка — правильная техника, переносится и в свой рендер.
3. Безопасность сохранения: журнал, поколения, проверка нетронутых записей, атомарная замена,
   «безопасное удаление» ванильных рефов.
4. Модульная архитектура и реестр типов рефов (`EditorRefTypeRegistry`: Light, Marker, Volume,
   Vegetation) — расширяемо.

**Почему как основа для «замены CK» не годится:**
1. **Правишь рантайм, а не данные.** В живой игре скрипты, AI, Havok и `ExtraData` меняют объекты;
   нужен сложный `RuntimeIdentityMap`, чтобы понять, какой записи принадлежит реф. Всё, что
   игра не загрузила (нет 3D, не та ячейка, выключенный плагин), не редактируется.
2. **Базовые записи не редактируются вообще** — ни NPC, ни предметы, ни квесты, ни скрипты.
   Архитектура (снимок рефов → писатель) на это не рассчитана.
3. Нет ландшафта, создания мира/внешних ячеек, правки навмеша, ESL, ESM.
4. Падение игры = падение редактора; каждый вход — перезапуск игры; деплой только после выхода.
5. Плагин должен быть уже активен в load order и загружен игрой.
6. Исходников нет, лицензия неизвестна — брать **идеи**, не код.

## 3. Creation Kit: что именно плохо и что нужно повторить

CK 1.5.73 (`C:\Skyrim\CreationKit.exe`). Проблемы: однопоточная загрузка всех мастеров (минуты),
падения на больших load order и ESL, Use Info медленный, UI Win32-диалогов 2011 года, нет поиска
по полям, нет нормального undo, render window с тормозами, не понимает MO2 без VFS-запуска,
ломает кириллицу, навмеш-генератор и finalize капризны, «грязные» правки (ITM/UDR).

Функционал CK, который реально используют (с приоритетом для нас):

| Область | Что | Приоритет |

## 4. Варианты архитектуры

| | A. В игре (как концепт) | B. Отдельная программа | **C. Отдельная + live-link к игре** |
|---|---|---|---|
| Редактирование всех записей | нет | да | да |
| Картинка | идеальная | своя (приближение) | своя + «посмотреть в игре» |
| Стабильность | падает с игрой | своя | своя; игра — опционально |
| Ландшафт/навмеш/ESL/ESM | очень трудно | да | да |
| MO2 | костыль с публикацией | читаем профиль напрямую, пишем в папку мода | то же |
| Объём работы | средний, но тупик | большой (рендер) | большой + небольшой SKSE-плагин |

**Рекомендация — C.** Ядро и UI — отдельная программа, которая работает с данными (а не с рантаймом).
Рендер свой, уровня «лучше CK» (CK тоже рисует приближённо). Live-link — небольшой SKSE-плагин
(наш опыт CommonLibSSE-NG + идеи концепта: свободная камера, подмена центра грида): «показать это
место в игре», синхронизация камеры, горячая подгрузка правок рефов без перезапуска.

## 5. Чем закрываем основные технические риски

| Риск | Решение |
|---|---|
| Порча плагинов при записи | «хирургическая» запись: нетронутые записи копируются сырыми байтами, пересериализуются только изменённые; проверка round-trip; бэкап; атомарная замена; журнал восстановления (идея концепта) |
| Потеря строк (уже ловили: копия через MCP теряла локализованные строки) | явные параметры кодировки на плагин (UTF-8 / cp1251 / localized .STRINGS), тест: прочитал→записал без правок = тот же файл |
| Скорость на 289 плагинах / 1.4 млн записей | Mutagen overlay (ленивое чтение), фоновая индексация в SQLite с кэшем по отпечатку файлов (опыт SkyrimBridge: полный reindex уже работает), Use Info из индекса |
| NIF | генерация C#-кода чтения/записи из `nif.xml` (niftools, BSD) — все блоки, включая неизвестные нам, сохраняются при записи |
| Текстуры | DDS BC1–BC7 грузятся в D3D11 напрямую, без декодирования |
| BSA и приоритеты ассетов | свой VFS: приоритет модов MO2 + loose > BSA, порядок BSA по плагинам и ini |
| ESL | BEES 1.2 стоит в сборке → header 1.71, диапазон 0x000–0xFFF доступен; при этом можно включать строгий режим 0x800–0xFFF |
| Свойства скриптов без исходников | читаем `.pex` (там есть имена и типы свойств) — CK для этого требует `.psc` |
| Удаление ванильных рефов | только «безопасное»: disable + enable parent на игрока + опускание (как xEdit/концепт) |
| Внешние persistent-рефы | понимаем persistent-ячейку мира, перенос рефа между ячейками при перемещении через границу |

## 6. Что берём из своих наработок

- **SkyrimBridge** (`C:\dev\SkyrimBridge`): чтение профиля MO2 (`Mo2LoadOrder`, разные кодировки
  `plugins.txt`/`loadorder.txt`), FormID↔FormKey с ESL, SQLite-индекс, поиск скриптов в BSA.
  Переносится почти как есть.
- **SkyrimRE** (`C:\dev\SkyrimRE`): нужен в основном для live-link плагина (камера, стриминг ячеек,
  спавн, `LoadedLandData`), и при необходимости — для разбора поведения CK (`CreationKit.exe`
  1.5.73) в местах, где формат не задокументирован (navmesh finalize, facegen).
- **STB-Minimap**: парсинг LAND и навмеша (раскладка вершин, флаги треугольников).
- **C:\dev\ESP**: Spriggit-воркфлоу — можно сделать экспорт/импорт JSON для git-диффов.
